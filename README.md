# 🍽️ next Dinner Planner（晩御飯提案アプリ）

※ここから派生していく・・・

## 1. プロジェクト概要
アルバイト先での会話をヒントに、「毎日の献立を考えるのが大変」「冷蔵庫の余り物を使い切りたい」という悩みを解決するために作るアプリです。
昨日の晩御飯と、今日使いたい食材を入力すると、昨日と味やジャンルが被らないようなレシピをデータベースから探して提案してくれます。

### 解決したい課題・目的
1. **献立考案のストレス軽減:** 毎日「何を作ろう」と悩む時間をなくし、履歴を活用してマンネリ化を防ぎます。
2. **食品ロスの削減:** 冷蔵庫の余り物を優先的に消費できるレシピを提案し、食材を無駄なく使い切ることをサポートします。

## 3. 主要機能とUI/UX設計
スマートフォンからの利用（キッチンで冷蔵庫を見ながらの操作）を想定し、モバイルファーストなUIとしています。
↑できればいいな...

### ① 条件入力画面（Home）
- **履歴連携:** 前日に食べたメニュー（または和・洋・中などのジャンル）を入力。
- **タグ型食材入力:** 使いたい残り物食材を入力すると、JavaScriptで動的にタグ（バッジ）として追加される直感的なUI。
- **非同期通信:** 画面遷移を挟まず、Fetch APIを用いてスムーズにバックエンドへ検索リクエストを送信。

### ② 提案結果画面（Result）
- **ジャンルバッジ表示:** 提案されたレシピが「和食」「あっさり」など、昨日と被っていないことを視覚的に証明。
- **使用食材のハイライト:** 入力した食材がレシピ内でどう使われるかを強調表示。
- **履歴保存アクション:** 「これで決定！」ボタンを押すことで、データベースの食事履歴テーブルに記録され、次回以降の除外ロジックの精度向上（データの循環）に繋げます。

---

## 4. データベース設計
レシピと食材の多対多（N:M）の関係を中間テーブルを用いて正規化し、柔軟な検索・除外ロジックを実現します。

### 主要テーブル構成
1. `users` : ユーザー情報
2. `recipes` : レシピデータ（料理名、ジャンル[和/洋/中]など）
3. `ingredients` : 食材のデータ
4. `recipe_ingredients` : レシピと食材を紐付ける中間テーブル
5. `meal_histories` : ユーザーの食事履歴（昨日食べたレシピの特定に使用）

### 検索・除外ロジックの仕組み
1. `meal_histories` から昨日のレシピジャンルを特定。
2. `recipe_ingredients` から指定食材を含むレシピ群を抽出。
3. 抽出したレシピ群から、昨日のジャンルと一致するものを除外してフロントエンドへ返却。
